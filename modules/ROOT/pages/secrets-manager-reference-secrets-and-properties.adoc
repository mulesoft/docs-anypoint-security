= Referencing Secrets and Protected Properties in Anypoint Platform

Anypoint Secrets Manager stores TLS artifacts for Anypoint Platform services such as API Manager and Flex Gateway; Mule applications use Runtime Manager Protected Properties or the Secure Configuration Properties module for sensitive values. Each method has a different configuration location and placeholder syntax (for example, `${db.password}` or `secure::`). Use Secrets Manager when Anypoint Platform consumes TLS; use application properties when your Mule code must read the value at runtime.

== Secrets Manager Versus Application Properties

Use secrets manager when:

* You need platform-level TLS artifacts (TLS contexts, keystores, truststores, certificate resources) consumed by supported services such as API Manager (HTTPS proxies), Flex Gateway, or Runtime Fabric ingress.
* You want centralized lifecycle and rotation of these artifacts without changing application code.
* Artifacts are selected or referenced in the Anypoint Platform UI or CLI, as Mule application code does not read these values directly.

Use application properties when:

* Your Mule application code needs to read the value at runtime (for example, database passwords, OAuth client secrets, tokens, endpoints).
* You reference values in configuration with standard placeholders like `${db.password}` or in DataWeave with `p("db.password")`.

[NOTE]
====
Secrets manager isn't a general-purpose key/value store for application variables. Configure items you expect to resolve in code with `${...}` as application properties (*Protected* in Runtime Manager UI or via the Secure Configuration Properties module). Items in Secrets Manager aren't visible in the Secrets Manager list.

TLS artifacts stored in Secrets Manager are selected in Anypoint Platform service configurations (for example, choosing a TLS context in API Manager for an HTTPS proxy, or referencing a secret in Flex Gateway or Runtime Fabric ingress). Mule applications don't read these artifacts via `${...}` placeholders.
====

== Reference Application Credentials (Passwords, Keys)

To use sensitive values (like ${db.password}) inside your Mule application code, use one of these methods based on your deployment target:


[cols="1,2,1",options="header"]
|===
| Method | Where to Configure | Reference Syntax
| Protected Properties | Runtime Manager UI in *Settings > Properties* (select *Protect* for sensitive values) | `${db.password}`
| Secure Configuration Properties | In the Mule project in encrypted `.properties` or `.yaml` files with the Secure Configuration Properties module | `${secure::db.password}`
|===

Protected values are encrypted and stored by Anypoint Platform and don't appear in the secrets manager list. They’re shown only as property keys in app *Settings*.

=== Examples

Mule configuration (XML):

[source,xml]
----
<db:mysql-connection host="${db.host}"
                     user="${db.user}"
                     password="${db.password}"/>
----

DataWeave:

[source,dw]
----
%dw 2.0
output application/json
---
{ pwd: p("db.password") }
----
